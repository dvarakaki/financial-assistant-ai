Pré-requisito

O Assessor da etapa 5.2 no ar: chat, grafo, GEMINI_API_KEY e GROQ_API_KEY no .env. Avaliação da resposta (alucinação, nota de qualidade) fica para a próxima aula.

o buraco

O terminal não responde à pergunta

Um print mostra um pedaço do que aconteceu naquela hora, naquela máquina, se alguém estava olhando. Amanhã o processo reiniciou, o print sumiu, e a pergunta continua: por que aquele turno levou 18 segundos?

Qual nó

Guardrail, roteador, financeiro, agenda, orquestrador. O print da resposta final não diz quem consumiu o tempo.

Qual modelo

O especialista promete Gemini e cai no Groq se o Gemini falha. Sem registro, o fallback é invisível.

Quanto custou

Cada chamada gasta tokens de entrada e de saída, com preços diferentes. A resposta em português não traz a conta.

O que o projeto já tinha

O estado do grafo já calculava rota e agentes_chamados. executar_fluxo_assessor devolvia só o texto e descartava o resto. Observar, aqui, começa por parar de jogar fora o que o sistema já sabia.

conceito

Observar é conseguir explicar um caso

Um sistema é observável quando, de fora, você explica por que ele se comportou daquele jeito, usando sinais que ele mesmo emitiu. A pergunta pode ser nova. Você não precisa ter adivinhado, na semana passada, que ia querer saber o custo daquele turno.

01EmitirO código anota tempo, modelo, tokens, rota, erro. Sem isso, não há o que investigar.
02GuardarO sinal fica num registro, num trace, num log. Memória do processo já serve para a aula.
03Perguntar“Por que este turno passou de 8 s?” A resposta sai dos sinais, não de uma nova teoria.
No Assessor

Um turno é uma mensagem do usuário. Explicá-lo é dizer a rota, os modelos, os tokens, o custo, a latência e se terminou em ok, erro ou bloqueio.

conceito

Monitorar é vigiar um limite

Monitorar é olhar, o tempo todo, para perguntas que você já escolheu. O painel existe para essas perguntas. O alerta existe para quando a resposta sai do combinado. Você não investiga um caso: você vê se o serviço, como um todo, ainda está dentro do que foi aceito.

Pergunta fixa

O p95 dos turnos desta execução está abaixo de 8 segundos? A taxa de erro está abaixo de 5%? O banner verde ou vermelho da tela é essa vigilância.

Número agregado

Média, percentil, soma de tokens, custo acumulado, quantos bloqueios. Um turno sozinho não responde. A faixa de big numbers responde.

sinais

Log, métrica e trace

Log

Um fato discreto, com hora. “Turno 16:09, rota financeiro, status ok.” Bom para ler um caso. Ruim para responder “qual a média da última hora?”.

Métrica

Um número que agrega: latência p95, taxa de erro, tokens, custo. É o que o painel mostra em destaque. Perde o detalhe de um turno se você não guardar também a lista.

Trace

A árvore de um pedido: quem chamou quem, com duração e tokens em cada nó. É o que o LangSmith abre. A tela não redesenha essa árvore.

O que a tela guarda de propósito

Hora, latência, rota, status, tokens, custo, sessão. O texto do prompt fica no trace. O chat já mostra a resposta. A tela de operação não repete os dois — também porque esse texto é o que o anonimizador protege.

sre

SRE é confiabilidade com número

Site Reliability Engineering trata “o serviço está saudável?” como trabalho de engenharia. Há um limite combinado antes do usuário reclamar. Há um número que diz se o limite ainda vale. Há uma decisão quando o número estoura: parar de empilhar função e ir consertar.

Sinal clássicoA perguntaNo Assessor
LatênciaQuanto tempo o pedido leva?Média e p95 do turno
TráfegoQuanto trabalho está chegando?Quantidade de turnos nesta execução
ErrosQual fração falha?Turno em que o grafo levanta exceção
SaturaçãoO recurso está no limite?em andamento, um proxy frouxo. O modelo é API de terceiro: a fila da GPU não é nossa
Orçamento de erro, em uma frase

Se o acordo é “no máximo 5% dos turnos podem falhar”, esses 5% são o espaço de falha. Abaixo disso, dá para seguir construindo. Acima, a confiabilidade virou o trabalho da vez. A aula não opera esse orçamento; o banner só mostra se o limite está inteiro.

slo

SLI é a medida. SLO é o limite.

SLI

O indicador. No Assessor: latência p95 dos turnos guardados, e taxa de erro (exceções ÷ turnos). O p95 é o nearest-rank: ordena as latências e pega o menor valor que cobre 95% delas. Com 4 turnos, ele fica perto do máximo. A conta é a de produção; o número só firma com volume.

SLO

O objetivo. Nesta aula: p95 até 8 segundos e taxa de erro até 5%. slo_ok é os dois juntos. O banner pinta verde ou vermelho a partir desse booleano.

SLA, para fechar o trio

SLA é o mesmo tipo de limite quando vira contrato com consequência (crédito, multa, cláusula). Aqui não há contrato. Há um SLO de sala, escrito na API, para a tela não inventar o número.

Bloqueio não é erro

O guardrail de entrada que recusa um pedido está funcionando. Ele entra no big number de bloqueios e no status bloqueado. A taxa de erro do SLO conta só exceção. Senão, testar o guardrail pintaria o serviço de vermelho.

chatbot

O que se mede num chat de IA

Um chatbot gasta um caminho diferente a cada pergunta: às vezes só o roteador, às vezes ferramenta, às vezes fallback. Latência e custo balançam. Por isso a operação olha percentil e conta, não uma média solta.

O que um chat em produção ainda mede, e esta tela deixa quieto

Tempo até o primeiro token, se a resposta viesse em stream — o Assessor espera o turno inteiro. Sucesso de cada tool. E a nota da resposta, que é a próxima aula.

outros sistemas

IA sem conversa mede outra unidade

A unidade deixa de ser “a mensagem de uma pessoa” e passa a ser item, lote, consulta ou imagem. Saturação volta a importar quando o modelo roda na máquina de vocês ou quando o trabalho chega em fila.

SistemaO que a operação mede
Classificador
fraude, documento, imagem		Latência por item, itens por segundo, taxa de erro da API, custo por mil previsões. Fila e GPU entram se o modelo estiver na própria infra.
Lote
resumir 10 mil textos de madrugada		Duração do job, itens que falharam, tokens do lote, custo do lote, se o job terminou. Não há “usuário esperando um turno”.
RAG sem chat
busca que devolve trechos		Latência da busca, latência do modelo, tokens, consultas que voltaram vazias, custo por consulta.
Extração
PDF vira campos		Páginas por minuto, falha por arquivo, tokens, custo por documento, tamanho da fila.
Fala
áudio vira texto, ou o contrário		Latência por minuto de áudio, taxa de falha, custo por minuto. O token às vezes é segundo de áudio, não token de texto.
O que continua sendo avaliação

Acurácia, precisão, “o resumo inventou fato?”. Isso julga a qualidade da saída. A operação desta aula julga se o sistema respondeu, em quanto tempo e por quanto. As duas conversam; não são o mesmo número.

conta

Custo é token vezes preço

O provedor cobra por milhão de tokens, e entrada e saída têm preços diferentes. A saída do Gemini inclui os tokens de raciocínio. A tela usa uma tabela fixa, a publicada em outubro de 2026, sem desconto de cache — em aula a conta é o preço cheio.

ModeloEntrada / 1MSaída / 1MOnde
gemini-2.5-flashUS$ 0,30US$ 2,50Especialista (financeiro, agenda)
openai/gpt-oss-120bUS$ 0,15US$ 0,60Groq: roteador, guardrail, orquestrador, FAQ e o fallback
Por que o Groq pode ser “o mais usado”

Um turno de finanças chama o Groq várias vezes e o Gemini uma. O big number conta chamadas. A tabela por modelo mostra que o Gemini, sozinho, pode custar mais.

Não é a fatura

O LangSmith aplica a tabela dele. O centavo pode divergir. Reiniciar o servidor zera o acumulado: o registro vive na memória do processo.

O que vocês instalam nesta aula

Nada dessa pilha. Um módulo Python anota. Uma rota agrega. Uma página desenha. O LangSmith, mais adiante, mostra o trace que a página não desenha.

prática

Quatro peças, um JSON

novoobservabilidade.pyEscuta cada chamada de modelo e cada turno. Não entra no chat.
mudagraph.pyAbre o registro antes do invoke e fecha no finally.
novomonitor.pyGET /monitor transforma o registro nos big numbers.
mudamain.pyPublica a rota antes do mount do frontend.

A quinta peça é a página, arquivo novo, sem alterar index.html. Ela só desenha o JSON. A fórmula do p95, do custo e do SLO fica na rota — o mesmo JSON poderia alimentar um Grafana depois.

Primeiro app/observabilidade.py, senão o graph.py quebra no import. Depois o grafo, a rota, o main.py, por último frontend/monitor.html. Reinicie o uvicorn no fim.

Três produtos, uma família

LangChain, LangGraph e LangSmith são da mesma casa. Os dois primeiros são bibliotecas dentro do nosso Python. O terceiro é o site que recebe o rastro dessas bibliotecas.

LangChain

Biblioteca. Modelo, tool, mensagem, callback. O llm_rapido.invoke mora aqui.

LangGraph

Biblioteca, em cima do LangChain. O grafo de vocês: guardrail, roteador, financeiro, agenda. Não é um site.

LangSmith

Produto na nuvem, com tela em smith.langchain.com. Guarda o trace de cada invoke e mostra a árvore, os tokens e o custo.

Interface e biblioteca

As duas coisas. A interface é o site: lá se cria a conta, se lê o trace e se copia a chave. A biblioteca já veio dentro do LangChain que o projeto usa. Com o tracing ligado, cada invoke envia o run sozinho. Não há import langsmith no Assessor, nem chamada ao LangSmith dentro da rota /monitor.

O que é feito à mão

A tela do Assessor. observabilidade.py anota, /monitor soma, monitor.html desenha. Esse caminho não lê o LangSmith e não precisa de chave. O LangSmith é o segundo observador do mesmo turno: a gente só abre a torneira com três variáveis no .env.

Onde nasce a chave

Conta em smith.langchain.com. No site: Settings → API Keys → Create API Key. O nome do projeto a gente escolhe (assessor-aula). Se esse projeto ainda não existir lá, o primeiro trace cria. A chave cola no .env da pasta do Assessor, no próximo slide. Sem aspas. Sem commit.
